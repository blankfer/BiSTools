## Layout (BiSTools only)

- `BiSTools.toc`: the load order, and the only place the version lives (`## Version`, currently 0.3.3). It targets `## Interface: 20506`, declares `## SavedVariables: BiSToolsDB` and `## OptionalDeps: BiSTheme, FojjiCore`, and carries `## X-Curse-Project-ID: 1686340`. Load order: the embedded libs, then `Core\Init.lua`, `Core\Registry.lua`, `Core\Slash.lua`, then `Tools\TargetFarming.lua`, `Tools\FarmSpots.lua`, `Tools\Summon.lua`, `Tools\Hub.lua`. The order matters: `FarmSpots`, `Summon` and `Hub` all read `NS.Farm`, which `TargetFarming.lua` sets. `Hub.lua` must stay last.
- `Core/`: the small framework every tool plugs into:
  - `Init.lua` (88 lines): loads first. Sets up the namespace (`_G.BiSTools = NS`), `NS.VERSION` (read from TOC metadata; `VERSION_FALLBACK` must equal `## Version`, and the harness checks this), the palette `NS.T` (uses `BiSTheme` when present and looks it up lazily, falls back to an inline `FALLBACK` otherwise), `NS.Print` and `NS.DB()`. `BiSToolsDB` gets defaults `{ tools = {}, enabled = {} }`. There is no db version or migration counter. `NS.Comm` boots LibBiSComm on `ADDON_LOADED` and saves the `/biscomm off` switch in `BiSToolsDB.comm` on logout. The comm lib is not a tool, so switching tools off never turns it off.
  - `Registry.lua` (84 lines): `NS.Registry`. The header comment documents the tool table: `name`, `desc`, `usage`, `defaults`, `OnInit`/`OnLogin`/`OnSlash`/`OnEnable`/`OnDisable`/`OnOpen`, `options` (kinds `toggle|seg|step|button`) and `slashWhenOff`. Each tool's settings live in `BiSToolsDB.tools[name]`, and its on/off state in `BiSToolsDB.enabled[name]`.
  - `Slash.lua`: `/bist` (since 0.4.0, matching `/bish` and `/bisg`), with `/bistools` and `/bt` kept as aliases. With no arguments it lists the tools. `/bist on|off <tool>` switches one. `NS.HubSlash` handles `hub`/`options`/`minimap`, and anything else goes to that tool's `OnSlash`.
- `Tools/`: one file per tool. Each calls `NS.Registry:Register{...}`.
  - `TargetFarming.lua` (603 lines): the `farm` tool, which moves the skull to a fresh copy of your last kill. It also defines the shared UI kit `NS.Farm` (`F.color`, `F.tex`, `F.fs`, ...), which Summon and Hub use as `K`. Sections: kills, scan, sound, the prompt, target key, window, events.
  - `FarmSpots.lua` (606 lines): `NS.Farm.Spots`, the farm tool's spawn timers (zones and their subs, raid marks, the shelf). Not a separate tool. Sections: where am I, data, record, prune, target sync, callout, shelf.
  - `FarmGuide.lua`: `NS.Farm.Guide`, RestedXP's Active Targets as rows in the farm window (`F.Entries` appends them, tagged RXP, at most `G.MAX`). Hooks `LibStub("AceAddon-3.0"):GetAddon("RXPGuides").targeting:UpdateEnemyList` with hooksecurefunc - read-only, after theirs; tries at load, PLAYER_LOGIN and ADDON_LOADED RXPGuides. `/bist farm guide on|off` (`db.guide`).
  - `FarmArrow.lua`: `NS.Farm.Arrow`, a big floating arrow (`BiSToolsFarmArrow` on UIParent, draggable, `db.arrowPos`, shown only while `db.active`): points at the spot most likely up next by `S.Describe`'s sort key, tie to the nearer, this map only; redrawn 20/s by OnUpdate while shown; `/bist farm arrow on|off` (`db.arrow`). What is SHOWN - window, call-out, pins, arrow - follows `S.Shown(db)` = the farmed mob only; `S.Mob` (with its last-kill fallback) is for pruning.
  - `FarmPins.lua`: `NS.Farm.Pins`, the farm spots on the minimap and the world map through HereBeDragons-Pins - one raid-mark icon per spot and sub of the farmed mob (`S.Mob`), bright when up, dim while waiting; a 1 s ticker started by `F.Hook`, stopped by the farm tool's `OnDisable`; `/bist farm pins on|off` (`db.pins`). The suite cannot run the client's map engine, so it compiles the two HereBeDragons files and swaps in a strict stand-in that records pins.
  - `Summon.lua` (1224 lines): the `summon` tool (`NS.Summon`, `slashWhenOff = true`). It builds a ranked "who needs a summon" list, using facts from LibBiSComm peers and guesses for everyone else, plus the nag. Sections: pure logic, gather, state, stones, requests, freshness, the key, console, window, stone watcher, the nag, events, slash.
  - `Recap.lua`: the `recap` tool (`NS.Recap`), the death recap. Data: `RC.Fetch` (C_DeathRecap, newest first), `RC.Hits` (plain fields only; a hidden one is just missing), `RC.Summary` (attackers by **GUID** - Forever re-names a mob every hit - titled by the words their kind's names share, `RC.Shared`; killer = the newest hit's, assists = the two biggest others; totals only when every amount was plain). Window `BiSToolsRecap` (`RC.Build`/`RC.Paint`/`RC.Toggle`, 360 px, farm kit + prompt): three cards, a 10-column health strip (gold = crit), 6 hit rows, a total line. Opens on `PLAYER_DEAD` unless `db.popup` is false; closes on `PLAYER_UNGHOST`/`PLAYER_ALIVE` once you are not dead or a ghost. `/bist recap` toggles; `raw` prints the measuring snapshots (`RC.Read` at death, after the fight, now); `now` the live one. Measured 12 Oct (Ragefire Chasm, in combat, and a player kill): nothing hidden. Rivals in `db.rivals[name]` (`class`, `guid`, `added`, `kills`, `active` = gold, `seen`, `where`): a card click toggles one (`RC.ToggleRival`, new = gold); the header **+** opens the drawer (`RC.SetExpanded`, `db.expanded`, `RC.PaintRivals`: gold first, click = gold/silver, shift = forget). The tracker `RC.Spot` runs on `NAME_PLATE_UNIT_ADDED` / `PLAYER_TARGET_CHANGED` / `UPDATE_MOUSEOVER_UNIT`, stops at `RC.GoldCount == 0`, names via `NS.Farm.Name` (plain or nil), one call-out per rival per `RC.ALERT_GAP` (60 s), sound `db.sound`. Loads before `Hub.lua`.
  - `Rivals.lua`: the `rivals` tool ("rivals & pals", 14 Oct 2026), split out of recap: its switch gates the whole tracker (crosshairs, hearts, crowns, crest, target button, menu lines) while `recap` gates only the death window; the rival settings and `/bist rivals ...` live here. The engine and ALL the data stay in Recap.lua / recap's saved table, read through `RC.DB()` - nothing migrated. Loads right after Recap.lua.
  - `Box.lua`: `NS.Box`, the "BiS> tools" box (`BiSToolsBox`): adopts the farm's `F.TargetButton()` (dressed with the skull) and the recap's `RC.tbtn`, shows each only when it has work (`B.Buttons`), hides when empty; docks to `BiSHealingNowBlock`'s right edge when that is shown (hooked OnShow/OnHide), else `NS.DB().box.pos`, header-dragged out of combat and never while docked. `B.Refresh` is out of combat only (`B.dirty` -> `PLAYER_REGEN_ENABLED`); it wraps `R:SetEnabled` to relayout. Loads after `Recap.lua`, before `Hub.lua`.
  - `Social.lua`: the `social` tool (`NS.Social`): a random friendly emote (`S.EMOTES`, `DoEmote`) at a player whose buff lands on you - `UNIT_AURA` for "player", `addedAuras[i].sourceUnit`, every field asked first; out of combat and out of chat lockdown only; `S.MIN_GAP`-`S.MAX_GAP` (2-5 min) between emotes, `S.SAME_GAP` (10 min) per player; groupmates only with `db.groupToo`. OFF by default (`db.thanks`). `/bist social on|off|group|why`; `S.lastWho/lastWhy` for why.
  - `Threat.lua`: the `threat` tool (`NS.Threat`) - a BETA: `defaultOff = true`, title "threat (beta)", off until `/bist on threat`. Situations `T.STATES` (tank: mine/otherTank/nonTank/slipping/idle; dps: climb/onMe), each with a saved colour (`db.colours`) and on/off (`db.on`); read by `UnitDetailedThreatSituation` ("secret?" before ANY comparison; hidden = nothing, not "not on its list"); a tank's group look cached per mob `T.SCAN`. Looks `db.look`: crosshair (recap `RC.MarkPlate` kind `threat`, never covering another kind), marker (left of the plate), glow - our own frames on UIParent pinned to the plate. `T.Refresh()` redraws after any setting. Events only.
  - `ThreatWindow.lua`: `T.UI`, the customization window `BiSToolsThreat` (look/role segments, a row per situation with a check and swatches, a 16-colour palette, Show from / Flash from steppers, preview on a fake plate via `RC.NewMark` / `T.NewIndicator`, reset colours). `/bist threat` toggles it; the Hub's row opens it.
  - `Battleground.lua`: the `bg` tool (`NS.BG`), battlegrounds only (IsInInstance "pvp"): the scoreboard asked every `B.EVERY` s (RequestBattlefieldScoreData -> UPDATE_BATTLEFIELD_SCORE), read by `C_PvP.GetScoreInfo` (named fields, each asked "hidden?"; the old positional global is the fence's pair half and is never parsed). Forever hides the numbers mid-match, so `B.ReadOrder` reads the SORT ORDER instead (`SortBattlefieldScoreData` name -> healing -> kills, only while the window `PVPMatchScoreboard` is closed, not in the first `B.WARMUP` s). Enemy top 3 healing-class players wear white crossed sabers, the top killer red ones (`B.NewSaber(kind, look)`: Lines, five looks `B.LOOKS`, size/height steppers), on the body under the plate. A secure "mark" button in the tools box (`B.BoxButton`, a /target macro, written out of combat) and "BiS> mark" under the scoreboard (`B.Button`). Memory `db.known[name]` = {guid, healer, killer, last}: counted once per battleground; a known enemy is marked on sight (dim, steady) until this battleground's scoreboard has them (`B.onBoard`); 30 days unseen = forgotten, at most 300. Loads after `ThreatWindow.lua`.
  - `Rides.lua`: the `rides` tool (`NS.Rides`, 21 Oct 2026), ON by default (Arn: "BiS Tools enables the card"): the
    card `BiSToolsRides` at the top left in a ride's zone or its capital, POPPING UP only while a ride waits at the dock

    a second only where a ride is

    nothing ticks while hidden; hidden in instances. Hands the lib `db.clock` (`RideStore`) so the clock outlives a

  - `Sounds.lua`: the `sounds` tool (`NS.Sounds`, 5 Nov 2026), the sound explorer `BiSToolsSounds` (430x300):

  - `XP.lua`: the `xp` tool (`NS.XP`, 6 Nov 2026): two secure item buttons the BiS> tools box adopts (`B.Buttons`):

- `Libs/`: embedded copies of `BiSTheme/Console.lua`, `BiSTheme/Options.lua`, `LibBiSComm-1.0` and `RezComm-1.0`, all listed in the TOC. Since 0.4.0 also three THIRD-PARTY libs, unmodified from upstream at pinned commits: `LibStub`, `CallbackHandler-1.0` (Ace3, BSD) and `HereBeDragons` (Nevcairiel, BSD) - sources, commits and the license text in `Libs/THIRD-PARTY.txt`. Never edit them; replace from upstream. bislint and the fence skip them, as they skip every non-BiS lib. `RezComm` starts itself at login from its TOC line; nothing in `Tools/` calls it. See the libs rules in `../_bisdev/CLAUDE.md`.
- `dev/tests.lua` (1755 lines): the headless harness (`lua5.1 dev/tests.lua`, run from the addon root). It reads `BiSTools.toc` for the version and the file list, then loads every listed file in order, with no stubs, and calls each one as `chunk("BiSTools", NS)`. It asserts the TOC lists at least 9 files and that it lists `Libs/BiSTheme/Options.lua`. Sections: WoW mock (`_G.__W`), load, checks, spawn zones + spots, comm lib + summon tool, a full 25-man, RezComm, the Hub, wrong-accent pass, embedded libs are the canonical bytes. The last section compares the four `Libs/` files byte for byte against `../_bisdev/` and `../BiSTheme/`.
- `dev/theme.lua`: sets `_G.__THEME_MUTATION = "ff0000"`, then `dofile`s `tests.lua` to catch hardcoded accent colours. No other suite files exist (no options, stress, kit, harness or load files).
- `dev/Example.lua.txt` and `dev/FarmSpots.flat.lua.txt`: not loaded by anything. The first is a template tool (`ping`); the second is the older flat version of FarmSpots, kept for reference.
- `dev/release.ps1`: builds `BiSTools-<version>.zip` in Downloads (everything except `dev`, `.pkgmeta`, `.git`, `.gitignore`) and uploads it to CurseForge project 1686340. The version comes from the TOC and the changelog text from the top entry of `CHANGELOG.md`. Before zipping it checks the embedded libs' MD5s, but that list has only three files: `Libs\BiSTheme\Options.lua` is missing, although `tests.lua` does check it. Flags: `-Type beta|alpha`, `-ZipOnly`.
- `CHANGELOG.md`: one `## x.y.z` heading per version, newest first. `release.ps1` sends the top entry.
- `.github/workflows/check.yml`: calls the reusable CI workflow in `bisdev` with `addon: BiSTools`.
